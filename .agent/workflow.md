

| Block / Action Name | Flow Mechanics | Detailed Explanation | Setup Flow (Builder) | End User Result (Customer) |
| :--- | :--- | :--- | :--- | :--- |
| **Reply / Random Reply** | **Linear Progression:** Outputs content, then moves to the next block or waits for button clicks. | Sends a message to the user with text, images, videos, and clickable buttons. "Random Reply" selects one response from multiple variations. | Drag the block into the canvas. Type the text, upload media, or add buttons. For Random Reply, write multiple message variations for the bot to choose from. | The customer receives engaging, multimedia-rich responses. With random replies, returning customers experience varied greetings instead of the exact same scripted text. |
| **Agent Handoff** | **Flow Termination:** Stops the bot and transfers the chat to the human agent queue. | Seamlessly transitions the conversation from the AI to a human support agent. | Add the block to a specific path (e.g., when a user clicks "Talk to Human" or when AI fails to answer). No complex coding is required. | The customer is smoothly transferred to a live human representative to resolve complex issues, feeling heard and properly supported. |
| **If Operating Hours** | **Branching Node:** Evaluates the time and splits into "Open" and "Closed" paths. | Checks the current time against the company's predefined working hours. | Drag the block and draw two connection lines: one to a block for when the office is open, and one for when it is closed. | If reaching out outside business hours, the customer instantly receives an offline message (e.g., when the team returns) instead of waiting indefinitely. |
| **If Online Agent** | **Branching Node:** Splits the flow based on whether agents are "Online" or "Offline". | Checks the Tiledesk system to verify if human agents are currently online. | Add the block and connect the "Online" path to an Agent Handoff block, and the "Offline" path to a lead-capture form or ticketing block. | The customer gets human help if available, or is politely asked to leave their contact info/create a ticket if no one is online. |
| **Condition** | **Branching Node:** Evaluates a specific rule (e.g., counter > 2) and routes the flow accordingly. | Personalizes conversations by evaluating specific variables or scenarios. | Define a condition (e.g., "if variable user_language equals French") and route the flow down custom paths based on the outcome. | The customer experiences a personalized journey that adapts specifically to their inputs, language, or status. |
| **Set Attributes** | **Background Execution:** Runs silently and passes the flow to the next block. | Defines and stores custom variables (like an interaction counter or email). | Choose a variable name (key) and assign it a value (e.g., set `counter` to `counter + 1`) to be used later in the flow. | The customer doesn't see this happen, but benefits from a "smart" bot that remembers context (like their name or score) later in the chat. |
| **Capture User Reply** | **Pause & Wait:** Halts the flow until the user types a response, saves it, and triggers the next block. | Pauses the chatbot to record the user's textual response as a variable. | Add the block, type a prompt (e.g., "What is your email?"), and assign an attribute name (e.g., `userEmail`) to store the answer. | The customer answers questions naturally within the chat flow, creating a conversational, frictionless data-entry experience instead of filling out web forms. |
| **Replace Bot** | **Flow Jump:** Terminates the current bot's flow and triggers a completely different bot. | Switches the active bot handling the conversation to a different, specialized bot. | Add the block and select which pre-built bot to switch to from a dropdown menu (e.g., switch to a Spanish bot based on language). | The customer is seamlessly handed over to a specialized AI (like an onboarding bot or a specific language bot) without noticing the underlying switch. |
| **Change Department** | **Routing Node:** Halts the current flow and routes the chat to a different team queue. | Transfers the conversation to specialized human departments. | Add the block and select the target department (e.g., "Sales" or "Technical Support") from your workspace settings. | The customer is automatically routed to the correct team of human experts best suited to handle their problem. |
| **Wait** | **Time-Delay:** Pauses the flow for a predetermined amount of seconds before proceeding. | Introduces a timed delay to mimic human-like typing or processing. | Add the block and input the number of seconds you want the bot to pause. | The customer experiences natural pacing, giving them time to read previous messages rather than receiving instantaneous walls of text. |
| **Web Request** | **Integration Node:** Pauses briefly to call an external API, waits for the response, and proceeds. | Connects the bot to external tools (like HubSpot or weather services) to fetch or send data securely. | Configure the HTTP method (GET/POST), paste the API URL, add your authorization headers, and map the JSON response to variables. | The customer gets real-time, actionable updates directly in the chat (e.g., checking live order status) or has their data seamlessly saved to a CRM. |
| **Ask Knowledge Base** | **Retrieval & Branching:** Queries the RAG engine mid-flow. Outputs an answer if found, or triggers a fallback branch. | Queries uploaded documents, URLs, or FAQs to generate an AI response based strictly on company data. | Upload PDFs or URLs to your Knowledge Base. Add the block to your flow, and optionally select a specific Knowledge Base to query. | The customer asks a question and instantly receives a highly accurate, context-aware answer based on the company's manuals or website. |
| **GPT Task (ChatGPT Task)** | **Processing & Branching:** Pauses the flow to let the LLM analyze text or perform logic, saving the output. | Uses an LLM prompt to perform complex reasoning, analyze sentiment, or extract entities. | Add the block, write a system prompt (e.g., "Extract the user's email and name from this text"), and map the AI's output to variables. | The customer enjoys a deeply intelligent interaction where the bot can accurately understand complex requests or extract their details from natural sentences. |
| **Code Action** | **Background Execution:** Runs custom code silently and passes the flow to the next block. | Allows embedding custom JavaScript code directly into the flow. | Open the block's code editor and write custom JavaScript logic using `context.attributes` to manipulate variables. | The customer benefits from highly customized backend mathematical calculations or advanced logic executed instantly behind the scenes. |
| **Clear Transcript** | **Background Execution:** Silently wipes the chat history memory from the flow and proceeds. | Resets the conversation transcript in the background. | Simply drag the block into the flow where you want the conversation context to reset. | The customer experiences a clean slate for a new inquiry, preventing the AI from getting confused by the context of older, resolved conversations. |
| **ChatGPT Assistant** | **Autonomous Loop:** Suspends standard block flow and hands control over to the OpenAI Assistant API. | Integrates directly with OpenAI's Assistant API, adept at working with specific files and calculations. | Paste your dedicated OpenAI Assistant ID into the block and connect a "Reply" block to the success endpoint to output its responses. | The customer interacts with an AI capable of acting as an expert data-driven advisor (e.g., calculating pricing discounts based on a spreadsheet). |
