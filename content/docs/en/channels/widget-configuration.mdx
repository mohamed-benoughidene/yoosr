# Widget configuration

Beyond appearance, the Yoosr widget has several behavioral settings that control how visitors interact with it. All settings are in **Settings → Widget Setup**.

## Pre-chat form

The pre-chat form collects visitor contact information before the conversation starts. When enabled, a visitor who clicks the chat button sees a form instead of going directly to the chat window.

To enable or disable the form, toggle **Pre-chat form** in Widget Setup.

### Contact method

When the pre-chat form is enabled, you choose what contact information to collect:

| Contact method | Fields shown |
|----------------|-------------|
| `email` | Name + Email |
| `phone` | Name + Phone number |
| `both` | Name + Email + Phone number |

The visitor must fill in all shown fields to submit the form and start the conversation. The data is saved to their contact record in Yoosr and linked to every conversation they start.

<Callout variant="info" title="Contact records are created from form submissions">
If the visitor submits an email or phone that does not exist in your Contacts table, Yoosr creates a new contact record automatically. If the email or phone already exists, Yoosr updates the existing contact record with the latest conversation link.
</Callout>

### Disabling the form

When the pre-chat form is disabled, visitors go straight to the chat window after clicking the launcher button. Use this when you do not need to identify visitors up front — for example, on a public support site where anonymous questions are fine.

## Welcome delay

The welcome delay controls how many seconds after the widget loads before the welcome bubble appears next to the launcher button. The bubble shows a preview of the welcome message to draw attention to the widget.

The default delay is **3 seconds**. To make the bubble appear immediately on load, set the delay to `0`. To disable the bubble entirely, disable **Enable welcome notification**.

## Auto-close timeout

The auto-close timeout automatically resolves conversations that have been inactive for a set number of minutes. This prevents your queue from filling up with abandoned conversations.

The `autoCloseMinutes` setting controls this timeout. The default threshold is **30 minutes**. A cron job checks all open conversations and closes any where the `updatedAt` timestamp is older than `autoCloseMinutes`.

| `autoCloseMinutes` value | Behavior |
|--------------------------|----------|
| Greater than 0 | Inactive conversations are closed after this many minutes |
| 0 or not set | Auto-close is disabled — conversations stay open indefinitely |

<Callout variant="tip" title="Auto-close fires a webhook">
When a conversation is auto-closed by the timeout, Yoosr fires a `conversation.closed` webhook event. You can use this to trigger a follow-up email or CRM update. See the [webhook event reference →](/docs/webhooks/events).
</Callout>

## Assigning a bot to the widget

The widget does not run a bot by default. To give visitors an automated first response, assign an active bot to the project in **Settings → Bot**.

Once a bot is assigned, it receives new conversations and responds automatically. When a visitor's conversation is handed off to an agent — by a HITL Handoff block or by an agent clicking **Join** — the bot pauses and stops sending further responses.

## Widget and operating hours

The widget stays visible at all times, regardless of your operating hours settings. Visitors can always send messages. Your operating hours setting affects the **If Operating Hours** block in bot flows, not widget visibility.

If you want the widget to show different behavior outside business hours — for example, a message saying your team is offline — use the **If Operating Hours** block in your bot flow. See [Operating hours →](/docs/settings/operating-hours).

## Session behavior

The widget stores the visitor's session in `localStorage` under the key `yoosr_visitor_id`. This ID is used to look up the visitor's existing open conversation when they return to the page.

If a visitor clears their browser storage or opens a new incognito window, the widget treats them as a new visitor and starts a fresh conversation.

To reset the session during testing, use the **Reset Session** button in the Widget Setup preview. This clears the stored visitor ID for the preview frame without affecting real visitors.

## Rate limits

The widget HTTP endpoints enforce rate limits to protect against abuse:

| Endpoint | Limit |
|----------|-------|
| Create conversation | 5 per visitor per minute |
| Send message | 20 per visitor per minute (burst: 5) |

Visitors who exceed these limits receive a `429 Too Many Requests` response. The widget displays a generic error message.
