# Outbound webhooks

Yoosr uses a RestHooks pattern for outbound webhooks. You create a subscription that links a URL to one or more events. Yoosr delivers a signed HTTP POST to that URL every time a matching event occurs.

## How delivery works

When a subscribed event fires:

1. Yoosr builds the JSON payload and signs it with HMAC-SHA256 using your subscription's secret.
2. Yoosr sends a POST request to your URL with a 10-second timeout.
3. If the response status is 2xx, the delivery is marked successful.
4. If the response is any other status or times out, Yoosr retries.

Retries follow a fixed schedule:

| Attempt | Delay after previous failure |
|---------|------------------------------|
| 1 (initial) | Immediate |
| 2 | 1 minute |
| 3 | 5 minutes |

After three failed attempts, Yoosr stops retrying and marks the delivery failed. Check the delivery log to see the error and status code for each attempt.

<Callout variant="warning" title="Your endpoint must respond within 10 seconds">
Yoosr sets a 10-second timeout on each delivery attempt. If your server takes longer to respond, the delivery is marked failed and a retry is scheduled. Acknowledge receipt immediately with a 200 OK, then process the payload asynchronously.
</Callout>

## Creating a subscription

You need admin access to create webhook subscriptions.

1. In your dashboard, go to **Settings → Webhooks**.
2. Click **New webhook**.
3. Enter the URL that Yoosr should POST to.
4. Select the events you want to subscribe to. You can choose one or multiple.
5. Click **Save**.

Yoosr generates a cryptographically random 32-byte secret for each subscription. You use this secret to verify that incoming requests really came from Yoosr.

<Callout variant="tip" title="Copy the secret immediately">
The subscription secret is shown once when you create the subscription. Copy it to your secrets manager before leaving the page. You cannot retrieve it later — only recreate the subscription.
</Callout>

## Subscribing to multiple events

You can subscribe to any combination of available events in a single subscription. Yoosr delivers all matching events to the same URL. If you need different URLs for different events, create separate subscriptions.

Available events are listed in the [Webhook event reference →](/docs/webhooks/events)

## Managing subscriptions

From **Settings → Webhooks**, you can:

- **Pause a subscription** — Toggle the subscription off. Yoosr stops delivering events. The subscription and its secret are preserved. Re-enable it at any time.
- **Delete a subscription** — Removes the subscription permanently. Yoosr stops delivering events immediately. This action cannot be undone.

## Delivery logs

Every delivery attempt — successful or failed — is recorded. To view the log:

1. Go to **Settings → Webhooks**.
2. Click the subscription you want to inspect.
3. Open the **Delivery log** tab.

Each log entry shows the event name, the target URL, the attempt number, the HTTP status code Yoosr received, and the timestamp.

<Callout variant="info" title="Log retention">
Delivery log entries are retained for 30 days. Older entries are not accessible from the dashboard.
</Callout>

## Request format

Every POST request Yoosr sends has this structure:

**Headers**

```
Content-Type: application/json
X-Yoosr-Event: conversation.opened
X-Yoosr-Signature: sha256=<hex-encoded HMAC-SHA256 of the raw body>
```

**Body**

```json
{
  "event": "conversation.opened",
  "projectId": "jh7abc123...",
  "timestamp": 1713200400000,
  "data": {
    "conversationId": "jh7xyz456...",
    "projectId": "jh7abc123..."
  }
}
```

The `timestamp` field is a Unix timestamp in milliseconds (the value of `Date.now()` in JavaScript). The `data` object contains event-specific fields — see the [event reference →](/docs/webhooks/events) for the exact payload shape per event.

## Verifying the signature

Always verify `X-Yoosr-Signature` before processing the payload. See [Signature verification →](/docs/webhooks/signature-verification) for step-by-step code examples in Node.js, Python, and PHP.
