# Create your first project

A **project** is the configuration for one website or brand. It holds your widget settings, your bot, your knowledge base, your connected channels, and your team's conversation history. If you support two different websites, you create two projects — one for each.

## Before you start

You need a Yoosr account and an organization. When you sign up, Yoosr creates an organization for you automatically using your company name. If you skipped that step, go to your account settings and create one before continuing.

## How to create a project

When you sign in for the first time, Yoosr detects that your organization has no project and creates one for you automatically using your organization name. You are then sent directly to the dashboard.

If you want to create an additional project:

1. Open the project switcher in the top-left of the sidebar.
2. Click **New project**.
3. Enter a name — for example, `Main Website` or `Support Portal`.
4. Click **Create**.

The new project appears in your project switcher immediately.

## Find your Project ID

Your Project ID is a unique identifier that looks like `proj_abc123xyz`. You need it to embed the widget on your website.

To find it:

1. Go to **Settings → Widget Setup**.
2. Look at the installation code snippet — your Project ID is the value inside `projectId: "..."`.

<Callout variant="info" title="Keep your Project ID handy">
You will paste it into your website's code in the next step.
</Callout>

## What a project contains

Once created, a project has these sections you can configure:

| Section | What you configure |
|---------|-------------------|
| **Widget Setup** | Appearance, colors, welcome message, pre-chat form |
| **AI Settings** | Which language model to use, your OpenRouter API key |
| **Knowledge Base** | Documents and articles the bot can search |
| **Channels** | WhatsApp, Telegram, Messenger, Instagram connections |
| **Departments** | Teams within your organization |
| **Settings** | Labels, canned responses, operating hours, webhooks |

## One project per website

If you run multiple websites or brands, create a separate project for each. This keeps conversation data, bot settings, and widget configurations completely separate. Your teammates have access to all projects inside your organization.

<Callout variant="tip" title="Multiple projects, one team">
All teammates in your organization can see and work across all projects. You do not need to invite them separately for each one.
</Callout>
